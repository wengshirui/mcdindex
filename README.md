# MCDIndex · 城市麦当劳指数

> 麦当劳程序员创意开发大赛（M-CODE）参赛作品 · 基于麦当劳 MCP 的 Agent Skill
>
> **当前状态：可运行。** 指数引擎、采集器、SQLite 数据仓、演示页均已落地并有自测覆盖。
> 数据范围：**全国 337 个地级及以上行政区**，采样门店 5,817 家（2026-10-12 采集）。

## 一句话介绍

用户说「苏州」「新街口」或任意地址关键词，它就用麦当劳 MCP 把这座城市的
**同档门店密度、核心区覆盖、得来速占比**算成一个 0~100 的麦当劳指数，
并告诉你它在全国同级城市里排第几。

## 它解决什么问题

想横向比较不同城市的麦当劳供给，常见做法是查第三方商业数据库 —— 有授权门槛、口径不透明、
且拿不到"此刻真实在营业的"门店与菜单。本项目**只用麦当劳官方 MCP**，从零构建一套可复现的采集与计算口径。

一个必须说清的前提：MCP 的门店接口 (1) 单次固定只返回 5 家、无分页；(2) 经纬度恒返回 `0.0`，
入参也没有坐标字段。**所以拿不到门店绝对总数，也无法按坐标聚合。**

应对方式是**同构关键词采样**：所有城市用同一套关键词模板（城市名 + 最多 10 个区县 + 17 条通用道路 + 27 个通用 POI）轮询去重，再按 `storeCode` 去重。这样得到的仍是**采样下界**，
  但城市间的**相对**大小可比 —— 这也正是产品定义「只要同级别比较」的技术根据。

### 采样到底有多薄？用公开数据量出来

把 337 城的采样门店数按省加总，与窄门餐眼《麦当劳 2025 年终报告》（2025-12，全国 8,373 家）对照：

| 省份      |  采样 |  公开 |       覆盖率 |   | 省份      |    采样 |    公开 |       覆盖率 |
| ------- | --: | --: | --------: | - | ------- | ----: | ----: | --------: |
| 山东省     | 285 | 300 | **95.0%** |   | 江苏省     |   564 |   638 |     88.4% |
| 辽宁省     | 202 | 219 | **92.2%** |   | 浙江省     |   527 |   620 |     85.0% |
| 陕西省     | 107 | 120 |     89.2% |   | 福建省     |   358 |   422 |     84.8% |
| 湖北省     | 227 | 293 |     77.5% |   | 四川省     |   231 |   281 |     82.2% |
| 天津市     | 152 | 246 |     61.8% |   | 广东省     | 1,179 | 1,859 |     63.4% |
| **上海市** | 216 | 583 | **37.0%** |   | **北京市** |   202 |   615 | **32.8%** |

全国合计 5,817 / 8,373 = **69.5%**。注意两个方向的事实：

- **偏差方向与预测一致**：省级覆盖率与该省门店数的秩相关为 **−0.674** —— 门店越多的省市被低估越多。
  北京、上海只采到三成，山东、辽宁采到九成以上。
- 少数省份 >100%（安徽 114%、河南 105%），来自两处：县级市门店被相邻地级市的锚点也命中
  （实测跨城重复门店 113 家，占 2.0%），以及公开数截至 2025-12、而本次采集是 2026-10。

因此本项目的结论一律表述为**组内相对位置**，不表述为绝对门店数。
另做了一个稳健性检验：按省级覆盖率校正门店数后重排，前 20 名 **19/20 不变** ——
采样偏差会压缩分数差距，但没有扭曲榜单结构。

## 目标用户

1. **想换城市生活/工作的人** —— 用一座城市"遇见麦当劳的容易程度"当消费便利度的一个侧写。
2. **麦当劳门店规划与市场同事** —— 快速看某城市的供给结构（密度 / 得来速 / 核心区覆盖）在同省的位置。
3. **好奇麦门地理学的普通用户** —— 输入自己家门口的关键词，看它所在城市排第几。

## 核心功能

1. **城市指数**：输入「苏州」→ `MCDIndex 93.7，同组 337 城中第 13 名`，
   附三个分项（门店密度 97.0 / 核心区覆盖 83.9 / 得来速覆盖 97.0）与原始读数。
2. **地址探针**：输入任意地址/地标（「南京 珠江路 435 号」）→ **实时打 MCP** 拉出最近 5 家门店与距离，
   把该点位的「5 家门店半径」放进 5,792 个锚点的参照分布里定位，给出密度水位与所属城市的指数。
3. **全国排行榜**：337 城全量表，点行即看详情。

## 方法可信度（这是本项目的核心主张）

指数只做**组内相对比较**，所有分项一律取同级别城市内的百分位，同构采样的偏差在组内被抵消。
选维度时用**区分度门槛**筛掉了两个看起来合理、实则无效的维度以下为全国 337 城实测：

| 维度                | 相对极差       | 区间              | 处置          |
| ----------------- | ---------- | --------------- | ----------- |
| 门店密度              | 43.2×      | 0 ~ 216 家       | 计分，权重 0.55  |
| 核心区覆盖（市中心第 5 家距离） | 2.35×      | 848 ~ 9,775 m   | 计分，权重 0.25  |
| 得来速占比             | 1.00×      | 0% ~ 100%       | 计分，权重 0.20  |
| ~~价格篮子~~          | **0.285×** | ¥3,117 ~ ¥4,207 | **仅读数，不计分** |
| ~~营业时长中位~~        | 0.765×     | 11.0 ~ 24.0 h   | **仅读数，不计分** |

给近乎无差异的量做百分位，等于把测量噪声放大成 0~100 的排名差异。
因此引擎内置 **`MIN_SPREAD` 收缩护栏**：某维度相对极差低于 `0.30` 时，得分自动向 50 塌缩。

两点值得说明：

- **营业时长这次达标了（0.765×）却仍然不计分** —— 24 小时店与城市规模高度共线，
  计入等于把"城市大"重复计一次。
- **这个换尺度复测本身就是护栏有效的证据**：同一维度在江苏 13 城是 0.016×（被拦），
  在全国 337 城是 0.285×（仍被拦）。该拦的没放过。

一个顺带的产品结论：**全国 337 城同一个价格篮子的挂牌价极差不到三成，
但你遇到麦当劳的机会差了 200 倍以上。**

## 这个指数和「巨无霸指数」是什么关系

用一款高度标准化消费品的价格或门店分布，去反过来读一个经济体的结构，不是我们首创。
最著名的先例是《经济学人》1986 年推出的**巨无霸指数** —— 用各国巨无霸的售价去比较购买力平价。
此外，用连锁门店的密度去代理城市商业结构，也是城市研究里常见的做法。

MCDIndex 借的是同一套直觉 —— *一个高度标准化的连锁品牌，它的门店分布能反过来读出城市的某种结构* ——
但把口径从价格换成了密度：

|         | 巨无霸指数          | MCDIndex             |
| ------- | -------------- | -------------------- |
| 代理的是什么  | 各国货币的购买力平价     | **日常餐饮基础设施的可得性**     |
| 用什么口径   | 单个商品的售价（跨国比较）  | **只做密度；价格口径被实测否定**   |
| 价格为什么能用 | 跨国价格确实有差异      | 中国大陆门店挂牌价无区分度 → 不计分  |
| 输出什么    | 价格比值           | **组内百分位**，不推断门店绝对总数  |

**一句话立场**：巨无霸指数问的是「这个汉堡在这国折合多少美元」，
MCDIndex 问的是「你在这座城里多容易撞见一顿饭」。两者量的不是同一样东西 ——
所以 MCDIndex 不该被读成 GDP。

**它不是什么**（产品页上也明写了这三条）：

- **不是 GDP，也不是发达程度** —— 佛山第 3、重庆第 39，反映的是麦当劳在这两地布局策略的差别，
  而不是佛山比重庆发达。
- **不是消费能力** —— 价格维度没有计分，指数里不含任何消费金额。
- **不是门店绝对数** —— 它是采样下界，而且门店越密的市场反而越容易被低估。

至于「那它到底像不像 GDP」—— 有实测答案，见下一节。

WorkBuddy：左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，

把仓库克隆（或复制）到 WorkBuddy 的用户级技能目录：

```bash
git clone https://github.com/<your-github-username>/mcd-index.git \
  ~/.workbuddy/skills/mcd-index
```

> 仓库名建议就用 **`mcd-index`** —— 赛事里绝大多数项目都是 `mcd-` 前缀

目录名随意，只要里面直接是 `SKILL.md` 即可被发现。装好后在对话里说
「苏州的麦当劳指数是多少」就会被触发。

### 4. 使用

```bash
# 城市模式（离线，秒出）
python tools/report.py --csv        # 计算指数 + 刷新 demo/index.html + 导出 CSV

# 地址模式（实时调 MCP）
python tools/probe.py 南京 珠江路435号

# 采集（全国 337 城 ≈ 37,000 次 MCP 调用 / 30 并发约 20 分钟）
python tools/collect.py --national --workers 30
python tools/collect.py --national --resume --workers 30   # 中断就续跑，已采的不重打
python tools/collect.py --status                           # 只看库里现有多少，不发起调用

# 全国排名 + 外部基准对照（省级覆盖率校验 / GDP 秩相关 / 覆盖率校正稳健性检验）
python tools/national_analysis.py --top 20

# 自测：69 通过 / 0 失败 / 0 跳过
python tools/selftest.py --with-data
```

`demo/index.html` 是**自包含**页面（数据内嵌、不联网、无 CDN），双击即可演示，
也可直接当静态站部署。

## 数据怎么存

采集一轮全国要三万余次 MCP 调用、约二十分钟，所以数据分两层放：

|          | 位置                       | 说明                                                                                                      |
| -------- | ------------------------ | ------------------------------------------------------------------------------------------------------- |
| **工作库**  | `tools/out/mcdindex.db`  | SQLite。`probe` 表记录**每一次**探针的成败与错误码，是断点续采的依据；`store` / `drive_thru` / `price_*` 存观测本体。已 gitignore，属开发期资产 |
| **分发快照** | `data/observations.json` | 由工作库导出的 JSON，随仓库分发，离线演示页依赖它                                                                             |

好处有三个：**中断可续采**（`--resume` 只补缺失与瞬时失败的探针）、
**错误可归因**（一条 SQL 就能看错误码 × 关键词类型的分布）、
**分析不必重算**（聚合交给 SQLite，`src/mcdindex.py` 仍只吃内存字典，交付物零 I/O 的约定不变）。

## 已知局限

- **采样不是全量**：全国整体覆盖率 69.5%，但**非均匀** —— 山东 95%、辽宁 92%，
  而北京 32.8%、上海 37.0%、广东 63.4%。省级覆盖率与该省门店数的秩相关 −0.674，
  即门店越密低估越多。所以只给排名，不给绝对结论。
- **跨城边界门店会被重复计入相邻地级市**（实测 113 家，占 2.0%），汇总到省级时会有小幅虚高。
- **核心区覆盖维度**依赖 MCP 对城市名的文本锚点解析，锚点位置不完全可控；
  好处是它**不依赖采样饱和度**，因此比门店计数更抗偏差。
- **约 45% 的探针会返回「该锚点周边没有门店」**，且这个比例随关键词类型变化很大
  （城市名 86.9% 命中、区县 47.3%、通用道路仅 35.7%）。因为所有城市用的是同一套关键词模板，
  这个偏差在组内是均匀的，不影响相对排名。
- **菜单随时段变化**（早餐 / 正餐菜单不同），价格必须在同一批次内采集才有可比性。
- 37 个地级行政区（多为边远自治州/地区）采样后门店数为 0，未出现在排行榜中。
- **得来速占比**取自 beType=1（全部门店）与 beType=5（得来速）两轮独立采样的并集。
  不能用「得来速数 ÷ 门店采样数」—— 实测两轮交集很小（得来速在城市外围，最近 5 家多在市中心），
  分子并不是分母的子集。

## 全国前 20 名 vs 城市 GDP（2026-10-12 实测）

有人会问：这个指数是不是就是 GDP 排名换个说法？不是。三个数字说明问题：

|                              | 结果                        |
| ---------------------------- | ------------------------- |
| MCDIndex 前 20 与 GDP 前 20 的交集 | **15 / 20**               |
| GDP 前 50 中已采到的 50 城，秩相关 ρ    | **0.598**（中等正相关，非同一张榜）    |
| 按省级覆盖率校正后重排，前 20 变化          | **19 / 20 不变**（只有济南↔汕头一换） |

- **符合直觉的部分**：广州、北京、深圳、上海、成都、杭州、武汉、南京、苏州、天津、青岛、长沙、福州、宁波、济南
  同时进两个榜单 —— 消费市场成熟度与城市经济体量确实同向。
- **指数显著高于 GDP 的**：佛山（GDP #22 → 指数 #3）、东莞（#24 → #19）、惠州（#48 → #12）、
  大连（#29 → #11）、厦门（#32 → #17）。前四个全在广东或辽宁，指向的是
  **麦当劳的区域性布局密度**：广东一省 1,859 家，占全国近四分之一，
  其"每万人的麦当劳数"远超经济体量排名。
- **GDP 高但指数低的**：重庆（GDP #4 → 指数 #39）、无锡（#14 → #45）、西安（#20 → #35）、
  郑州（#16 → #43）。重庆尤其反直觉 —— 它 3,200 万人口、GDP 全国第四，但公开数据里
  麦当劳门店仅 66 家，本次独立采样得到 61 家，**两个独立来源互相印证**，说明这是真实的供给格局。
- **上海、北京的排名被采样偏差压低**：它们覆盖率只有 37.0% / 32.8%（全国最低一档），
  密度分虽然已是满分 100，但真实差距比分数显示的更大。校正后上海、北京仍在前 8，未发生翻转。

结论：**指数测的是"遇见麦当劳的容易程度"，不是经济总量。** 它与 GDP 中等正相关，
差异部分恰恰是麦当劳自身的区域布局策略 —— 这正是本指数有信息量的地方。
